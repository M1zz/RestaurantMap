# 맛 기록과 취향

코드: `RestaurantMap/Models/Taste.swift` · `Views/TasteViews.swift` · `Views/TasteProfileView.swift`

## 세 층

| 층 | 무엇 | 언제 | 어디 |
|---|---|---|---|
| 미식 기준 | 재료 · 조리 · 조화 · 개성 (얼마나 잘 만들었나) | 모든 방문 | `Gourmet.swift`, `GOURMET.md` |
| 기본 맛 | 진하기(담백↔진함) · 자극(순함↔자극적) | 모든 방문 | `TasteAxis.basic` |
| 계열 맛 | 계열에 딸린 취향 축 2~3개 | 접어 둔 "더 적기" | `TasteFamily.axes` |

- 맛 축은 **좋고 나쁨이 아니라 어느 쪽이었는지**를 적는다. 품질은 미식 기준이 본다. 둘을 섞지 않는다.
- 모두 1~5, 모두 선택. 고른 점을 다시 누르면 지워진다.
- 저장: `Visit.tasteData` 한 칸에 `{축 rawValue: 1~5}` JSON. 축을 더하거나 빼도 모델 · 백업을 고치지 않는다.
  `TasteAxis` 의 rawValue 는 저장 키라 바꾸지 않는다.

## 계열

| 계열 | 기본 제공 종류 | 축 |
|---|---|---|
| 기본 | 일반 · 피자 · 중식 · 한식 · 양식 | 없음 |
| 고기 | 스테이크 · 치킨 · 버거 | 굽기 · 기름기 · 육향 |
| 생선 | 초밥 · 일식 | 숙성 · 와사비 · 샤리 간 |
| 면 | 라멘 | 면 · 국물 |
| 디저트 · 커피 | 커피 · 디저트 | 단맛 · 식감 · 산미 |
| 술 | 와인 · 술집 | 바디 · 당도 · 산도 |

직접 만든 종류는 만들 때 계열을 고른다(`FoodCategory.family`). 옛 직접 만든 종류는 기본이다.

## 취향 탭 — 묻지 않고 기록에서 센다

레퍼런스: Vivino(평가에서 취향을 만든다) · 위스키 플레이버 맵(Dave Broom · Diageo, 축 두 개 위의 점) · Beli(비교 · 일치도, 아직 안 함).

- **맛 지도**: 가로 진하기 · 세로 자극. 기본 두 축을 적은 집이 방문 도장으로 찍힌다. 누르면 그 집이 열린다.
- **기록의 나**: 기본 두 축의 가중 평균. 무게는 그 방문의 별점(안 줬으면 3) — 별을 많이 준 쪽으로 끌려간다.
- **내가 생각하는 나**: `TasteProfile.selfDepth` · `selfKick`. 사용자가 찍는 점선 원. 무료.
- **자주 가는 종류**: 다녀온 날 합 · 단골 수로 위 셋. 무료.
- **기록이 말하는 취향 (Plus, `RestaurantFeature.tasteProfile`)**
  - 별점과 가장 같이 움직이는 미식 기준 (피어슨 상관 > 0.3, 별과 기준을 함께 적은 방문 5번 이상).
  - 계열마다 축의 가중 평균 (그 계열 맛을 적은 방문 3번 이상).

## 옛 맛 평가에서 옮기기

옛 화면은 종류마다 여섯 칸(0~10 강도 + 1~5 만족도)을 받았다. `TasteMigration` 이 앱을 열 때 · 백업을 되살릴 때
뜻이 같은 칸만 옮긴다(`v / 2.5 + 1` 반올림). 만족도 칸은 옮기지 않는다 — 품질은 미식 기준이 본다.

| 옛 칸 | 새 축 |
|---|---|
| 진한맛 · 맵기 | 진하기 · 자극 |
| 스테이크 굽기 · 마블링 · 육향 | 굽기 · 기름기 · 육향 |
| 초밥 와사비 | 와사비 |
| 라멘 면발 · 국물 | 면 · 국물 |
| 와인 바디 · 산도 | 바디 · 산도 |
| 커피 산미 · 바디 · 단맛 | 산미 · 식감 · 단맛 |

옛 화면은 손대지 않은 칸도 5로 저장했다. 한 종류의 여섯 칸이 모두 5(또는 비어 있음)면 고르지 않은 것으로 보고 옮기지 않는다.
옛 칸은 iCloud 틀과 옛 백업을 읽으려고 모델에 남아 있지만 더 쓰지 않는다.
